# Sprint Contract: T-012 — Data schema definitions

## Planner Context
- Product slice: TypeScript type definitions for all game data (generals, skills, cards, factions)
- Why now: Every data consumer (engine, AI, web) depends on these shared types

## Generator Proposal
- User-visible outcome: Importable TypeScript interfaces from @sgs/data
- Files / interfaces to touch: packages/data/src/types/*.ts, packages/data/src/index.ts
- Verification plan: `pnpm --filter data build`
- Risks: Schema must be flexible enough for 341 generals with varied skill types

## Evaluator Gate
- Required acceptance criteria: TypeScript interfaces compile, exported from packages/data
- Required verification commands: `pnpm --filter data build`
- Rubric dimensions: Scope Fidelity, Functionality, Quality/Craft, Integration Safety

## Final Contract
- Scope: Define General, Skill, Card, Faction, FAQ TypeScript interfaces. Include all fields from the design spec (id, name, title, faction, subfaction, hp, gender, skills, image, paired, pairedNames, isEmperor, pack for General; similar detail for Skill, Card). Export from index.ts.
- Done means: `pnpm --filter data build` succeeds, types are importable from @sgs/data
- Out of scope: No actual data JSON files, no parsing scripts, no validation logic
- Contract status: approved
