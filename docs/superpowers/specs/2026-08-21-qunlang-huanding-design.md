# 群狼环鼎武将包替换 — 设计文档

日期：2026-08-21
状态：待评审

## 1. 背景

站点 `110-sgs-wiki` 当前的武将库是「国战」包：341 条武将数据 + `assets/generals/` 下 343 张 PNG，经 jsDelivr 从 GitHub `@main` 回源。

用户提供了一套新素材 `c国战 - Copy.zip`（492 文件 / 1199 MB），是**同卡号、不同称号、不同画**的另一版重制（例：`QUN003` 貂蝉从「舞惑群心」改为「傀戏红尘」）。本次工作是用这套素材**整体替换**现有武将库，包名定为「群狼环鼎」。

### 1.1 素材清单（实测）

| 目录 | 文件数 | 体积 | 内容 |
|---|---:|---:|---|
| 魏 / 蜀 / 吴 / 群 | 93 / 89 / 90 / 97 | 992 MB | 单势力武将卡 |
| 双势力 | 16 | 43 MB | 双势力武将卡 |
| 十常侍 | 13 | 28 MB | 10 张子卡 + 休整正背 + 十常侍背面 |
| 标记牌 | 48 | 94 MB | 24 组（正面 + 背面）技能标记 |
| 游戏牌 | 21 | 39 MB | 带花色点数的装备 / 锦囊 |
| 大攻车 | 15 | 4 MB | 图纸正背 + 12 零件 + 零件背面 |
| **合计** | **482** | **1200 MB** | |

### 1.2 与原始需求的两处偏差（已确认）

- 用户最初描述该包「有晋、5 个势力」。全量扫描 492 个文件名后确认**不存在晋势力**：势力代号只有 `QUN` / `WEI` / `WU` / `SHU`，另有 3 张 `AM`（司马昭、孙綝、公孙渊）和 4 张 `X&Y` 双势力。抽样解图复核，`AM001` 司马昭与 `WEI125` 司马师左上角均为**魏**徽记；文件名为 UUID 的散图是**杜预 `G.QUN110`**，归**群**。结论：本包为 4 势力，不做晋。
- 用户最初要求「和现有完全分开」，后改为**完全替换**。本文档按替换执行。

## 2. 已锁定的决策

| # | 决策 | 说明 |
|---|---|---|
| D1 | 完全替换 | 删除现有 341 条武将数据与旧图，不保留双包共存 |
| D2 | 只解析文件名，武将卡不读图 | 技能 / 体力 / 珠联璧合数据本次不产出 |
| D3 | 四类特殊牌全部收录 | 标记牌、游戏牌、大攻车、十常侍，并尽量关联到武将 |
| D4 | 图片转 WebP q85，不降分辨率 | 1200 MB → 约 100 MB |
| D5 | 只读 24 张标记牌正面 + 7 张双势力卡 | 共 31 张。标记牌 24 组中 11 组已可按文件名关联，解图对这 11 组起复核作用，另 13 组是真正未知的归属 |
| D6 | 武将名必须可被搜索 | 详见第 8 节 |
| D7 | 特殊牌建模用统一 `Token` 类型 | 方案 A，见第 4 节 |
| D8 | 保留现有 4 张君主牌 | 新包无此内容，不随替换删除 |
| D9 | 清空全部评分数据 | 替换后旧评分对应的是旧版武将，不再有意义 |

## 3. ID 策略与继承收益

新旧素材沿用同一套卡号，实测 ID 复用情况：

- **322 个 ID 同号同人** — URL 与评分数据自动继承
- 1 个同号不同名（`general_wei_187`：崔妃 → 崔令仪，同一角色改名）
- 53 个新增 ID，18 个旧 ID 消失

**因此不需要做 URL 重定向。** 用户提供的 `/generals/general_wei_014` 仍然是曹丕，仅称号由「魏文帝」变为「荡然由心」。

评分数据虽然技术上也能随 ID 继承，但按 D9 **一并清空** —— 旧评分是针对旧版武将投的，换版后不再有意义。

旧数据中 7 条 `subfaction` 有 5 条可直接搬运到新数据（刘琦、许攸、士燮、糜芳&傅士仁、孟达）。

## 4. 数据模型

### 4.1 `General` 新增三个可选字段

```ts
isAmbitionist?: boolean;      // AM001 司马昭 / AM003 孙綝 / AM004 公孙渊
parentGeneralId?: GeneralId;  // 十常侍 10 名子卡 → general_qun_000
```

> **执行期修订（2026-08-21）：原设计还有 `tokenIds?: TokenId[]`，已撤销。**
> 武将↔标记牌的关系单向存放在 `Token.ownerGeneralId`（见 4.2），详情页按该字段
> 反查即可。双向存储是冗余反范式，且会让 `general.ts` 与 `token.ts` 互相 import
> 形成类型循环。

### 4.2 新增 `Token` 类型（`packages/data/src/types/token.ts`）

```ts
export type TokenId = string & { readonly __brand: 'TokenId' };

export interface Token {
  id: TokenId;
  name: string;                 // 「羊祜」「上上签」「云纹」
  image: string;
  backImage?: string;           // 「XX背面」按文件名自动配对
  ownerGeneralId?: GeneralId;   // 能认亲的才有
  category: 'skill' | 'module' | 'misc';
  module?: string;              // category === 'module' 时为「大攻车」
}
```

产出 `packages/data/src/tokens.json`。收录范围：24 组标记牌（`skill`）、12 个大攻车零件 + 图纸（`module`，`module: '大攻车'`）、十常侍的「休整」牌与「十常侍背面」、现有 4 张君主牌 + 1 张共用背面（`misc`）。

### 4.3 `Card` 新增一个可选字段

```ts
image?: string;   // 21 张游戏牌
```

游戏牌以独立条目追加进 `cards.json`，与现有 108 张标准牌共存，靠 `image` 字段区分。

### 4.4 为什么不为每类特殊牌各建一个类型

标记牌、大攻车零件、休整牌、君主牌四者形状高度重合（名字 + 正面 + 可选背面 + 可选归属），差异只在语义分类。现有 `General` 和 `Card` 已能吃下十常侍子卡与游戏牌。为 97 张图养 4 套模型 + 4 份 JSON + 4 套 UI 不划算。代价是大攻车零件与技能标记同类型，用 `category` 区分。

## 5. 文件名解析规则

主正则（允许可选 `G.` 前缀、可选 `&副势力`、三到四位卡号带可选字母后缀）：

```
^国战UI\.(?:G\.)?([A-Za-z]+?)(?:&([A-Za-z]+))?(\d{3,4}[A-Z]?|XXX)\.(.*?)\.([^.]+)\.png$
                  └势力      └副势力          └卡号            └称号  └姓名
```

姓名段中的 `&`（如 `糜芳&傅士仁`、`王桃&王悦`）不会误判为副势力分隔符，因为副势力的 `&` 必须紧邻卡号数字。

### 5.1 六类边界情况

| 情况 | 数量 | 处理 |
|---|---:|---|
| 同卡号双版本：孔融 `QUN014`、诸葛亮 `SHU004`、张瑾云 `SHU097`、滕胤 `WU098` | 4 组 | 第二张加 `_b` 后缀：`general_shu_004` / `general_shu_004_b` |
| `XXX` 无卡号：8 名十常侍 + 魏讽 `WEIXXX` | 9 | 十常侍用 `general_qun_000_m01`…`m10`；魏讽用 `general_wei_xxx_weifeng` |
| `G.` 前缀：杨仪 `G.SHU091` | 1 | 正则吃掉 |
| 卡号带字母 / 四位：傅肜 `SHU085A`、王桃&王悦 `SHU093A`、罗贯中 `QUN1000` | 3 | 正则放宽为 `\d{3,4}[A-Z]?` |
| 文件名拼写错：`WEl174`（小写 L）国渊；标记牌 `全综`（卡面署名「全琮」） | 2 | 建修正映射表 |
| UUID 命名散图 `ab539b47-…png` | 1 | 已解图确认为杜预 `G.QUN110`，硬编码映射 |

### 5.2 双势力副势力（本次解图认定）

新素材的双势力文件名有 12 张丢失了 `&副势力` 段。其中 5 张从旧数据搬运，剩余 7 张通过裁取左上角徽记区解图认定：

| 卡号 | 武将 | 徽记 | `faction` | `subfaction` |
|---|---|---|---|---|
| QUN195 | 孟优 | 蜀 + 群 | `QUN` | `SHU` |
| SHU041 | 夏侯霸 | 魏 + 蜀 | `SHU` | `WEI` |
| SHU072 | 彭羕 | 蜀 + 群 | `SHU` | `QUN` |
| WEI168 | 黄权 | 魏 + 蜀 | `WEI` | `SHU` |
| WU050 | 潘濬 | 蜀 + 吴 | `WU` | `SHU` |
| WU070 | 苏飞 | 吴 + 群 | `WU` | `QUN` |
| WU071 | 许贡 | 吴 + 群 | `WU` | `QUN` |

判定依据为双色徽记与体力阴阳鱼的双色配色（蜀橙 / 魏蓝 / 吴绿 / 群白）。主副势力沿用文件名编码作 `faction`，另一侧作 `subfaction`，与旧数据 `WEI&WU072 → 唐咨` 的约定一致。

### 5.3 标记牌归属

48 张标记牌 = 24 组正背配对。按文件名匹配武将名可自动关联 11 组：羊祜、羊徽瑜、许褚、马钧、黄权、邓芝、荀谌、曹髦、冯熙、郭照（红 / 黑两套）。

剩余 13 组（签系列 6 组、全综、明鉴、矫诏、许身、福利卡、大攻车图纸、大攻车技能）需解图认亲。抽样验证可行：`全综.png` 右下角署名「**全琮技能卡**」，文件名为错别字，卡面自带归属。认不出的留 `ownerGeneralId` 为空，归入独立标记牌区。

## 6. 图片管道

`scripts/qlhd/convert-images.py`（Pillow 12.1.1 已装；仓库已有 `scripts/ocr-generals.py` 先例）

- 输入：解压目录
- 转 WebP `quality=85, method=6`，**不改分辨率**（原图 1098×1542）
- 输出：`assets/generals/`、`assets/tokens/`、`assets/cards/`
- 中文原文件名保留，仅换扩展名，沿用现有 jsDelivr 路径习惯

实测压缩比：2.71 MB PNG → 约 220 KB WebP（约 12×），卡面小字仍清晰。全量 1200 MB → 约 100 MB。

## 7. 数据管道

`scripts/qlhd/build-data.ts`（TS + tsx，配合仓库已有的 vitest 写解析器单测）

产出：
- 重写 `packages/data/src/generals.json`
- 新增 `packages/data/src/tokens.json`
- 更新 `packages/data/src/cards.json`（追加 21 张游戏牌）
- **清空 `packages/data/src/skills.json` 为 `[]`**（见第 8 节）

## 8. 搜索

全站搜索是 `packages/web/src/components/search/search-data.ts` 在**构建期**从 JSON 生成的静态索引，与 Redis 无关。武将按 `name + title` 索引，因此 D6「名字可搜」自动成立。三处改动：

1. **清空 skills.json 消除索引污染。** 现有 442 条技能里 335 条名字都叫「未知」，全部进了搜索索引，导致搜任意字都会撞出大量同名条目。本次不产出技能数据，清空后搜索结果显著变干净。
2. **`Token` 条目加入索引**，新增 `SearchResultType` 的 `"token"` 分支，标记牌 / 大攻车零件 / 君主牌按名字可搜。
3. **十常侍 10 名子卡进搜索但不进 `/generals` 主列表**（避免 10 条无称号条目），链接指向父卡 `general_qun_000` 详情页。

## 9. 站点改动

- `/generals` 列表：逻辑不动、数据换掉；势力筛选隐藏条数为 0 的晋
- `/generals` 的**体力筛选（`HpFilter`）隐藏** —— 全部武将 `hp` 为占位值 4，基于假数据的筛选是坏 UI。排序选项本来就只有「按名称 / 按编号 / 按势力」，无需改动
- `/generals/[id]` 详情页：**体力红心区隐藏**（同样是假数据）；新增「关联标记牌」区；十常侍详情页列出 10 名成员；技能区在 `skills` 为空时已自动隐藏（现有 `hasOnlyPlaceholderSkills` 判断对空数组返回 `true`），无需改动
- `/cards`：新增「群狼环鼎新增牌 / 标记牌 / 大攻车」分区
- **不新增顶级路由**

## 10. Redis 替换

页面数据读自 Redis（`entity-store.ts`），JSON 仅作降级回退，因此换数据必须同时更新两侧。

`scripts/seed-redis.ts` 新增 `--replace` 模式，按 D9 清空以下全部键后再灌新数据：

```
general:*   generals:index
skill:*     skills:index    skills:by-general:*
ratings:all ratings:log:*
```

缺这一步的话，18 个消失的旧 ID 会作为幽灵条目残留在 `generals:index` 里继续渲染。

现有 `scripts/clear-rating.ts` 只能按单个武将 ID 清，不适用于全量清空，本次不改动它。

## 11. 验证

1. **解析器单测**（vitest）覆盖第 5.1 节六类边界情况，逐条断言
2. **生成后断言**：无重复 ID；每条 `image` 在 `assets/` 下真实存在；标记牌正背配对无孤儿；`generals.json` 条目数为 **395**（385 张武将卡 + 10 名十常侍子卡）；`tokens.json` 与 `cards.json` 合计覆盖余下 97 张特殊牌
3. **端到端抽查**：`pnpm dev` 后检查列表页、曹丕详情页（`general_wei_014`，验证 URL 继承）、十常侍详情页、`/cards`、全站搜索输入「羊祜」应同时命中武将与标记牌

## 12. 明确不在本次范围内

- **技能、体力、珠联璧合数据**。这是 D2「只读文件名」的直接后果，替换后站点在这方面与现状一致（都是空的）。体力值其实可从卡面阴阳鱼数量单独跑一轮裁角识别补齐，无需重读全图，留作后续。
- **晋势力**。本包不含，`Faction` 类型保留 `'JIN'` 定义不动。
- **AI / engine 两个包**。本次不触碰。
